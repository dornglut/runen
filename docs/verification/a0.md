# A0 Verification Contract

Status: **non-normative conformance-oracle documentation**

This document owns the test obligations for the executable A0 oracle. The normative semantics exercised by A0 are owned by `spec/language/core/value-storage.md`.

## Core MIR admission boundary

Raw `runen-core-ir::Body` is a construction/data form. It is not executable by the reference machine until `validate_body` admits it as `ValidatedBody`.

Admission owns only structural and statically decidable constraints represented by the current MIR. It rejects unresolved identifiers and types, recursive by-value type graphs unsupported by the current representation, invalid block targets and place projections, operand/value type mismatch, `Copy` of a non-copy type, and `Assign` through an immutable local.

The reference machine accepts only `ValidatedBody`. Path-state-dependent A0 checks remain executable-oracle violations in this proving slice: `Init` requires Never-initialized storage; reads, moves, and copies require fully initialized storage; explicit `Drop` requires at least one Live subobject.

Those execution violations are negative verification results. They are not defined Runen `Fault` outcomes. A represented `Terminator::Fault` is instead a successful defined terminal execution and performs the cleanup required by the normative value/storage semantics.

## Required cases

The A0 suite covers at least:

- move invalidates the source;
- copy preserves the source;
- partial move preserves disjoint live sub-places and makes the aggregate unreadable as a whole;
- independently initialized fields can form a fully initialized aggregate;
- non-copy values cannot be copied, rejected at MIR admission;
- `Init` cannot reinitialize Dead storage;
- mutable `Assign` can initialize Never-initialized storage;
- mutable `Assign` can reinitialize Dead storage;
- mutable `Assign` can replace partially initialized aggregate storage while destroying only live old subobjects;
- immutable assignment is rejected at MIR admission;
- assignment destroys a live replacement target before writing the new value;
- explicit partial-aggregate drop destroys only live subobjects;
- moved or already-dropped values are not destroyed twice;
- field and local cleanup order matches the normative value/storage semantics;
- defined fault cleanup destroys each live value exactly once.

## Semantic instrumentation boundary

`Statement::Read` is a proving-kernel action for the normative Core read precondition. Its current zero-result MIR form exists so tests can exercise readability without introducing later computation semantics; the statement does not itself define a language-observable event.

`ScalarType::Tracked` and `Value::Tracked` are synthetic non-copy fixture values with observable destruction solely to make ownership and destruction behavior testable. They are not Runen language scalar or value primitives.

`runen-reference::TraceEvent` and `ExecutionReport::trace` are verification instrumentation. Read, move, copy, write, and fixture-drop records expose the reference machine's internal semantic transitions to tests; they are not the observable program trace defined by `spec/language/behavior.md`.

## Oracle independence

The oracle must model Runen state explicitly. Host ownership, host destruction, native addresses, allocator identity, container order, and host scheduling are not semantic oracles.
